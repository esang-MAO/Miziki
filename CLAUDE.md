# Miziki

A local-first music player for iPhone (installed from Safari to the home screen), served from GitHub Pages at
https://esang-mao.github.io/Miziki/miziki.html. It plays FLAC, WAV, ALAC and MP3 files the user picks from their device. Nothing is uploaded. An optional social layer (Supabase) sits on top, and the player must work fully without it.

Long-term plan: modularize the codebase, build out the Supabase social layer, then wrap the app with Capacitor for the App Store.

## Repo layout

- `miziki.html` holds the markup. The main player script used to be one big inline `<script>` block at the end of `<body>`; it now lives in `src/main.js` (step 2a), loaded via `<script type="module" src="src/main.js">` in that same position. It is still one big ~10,100-line file — splitting *that* up is the rest of step 2 and beyond. See "Refactor rules" below.
- `src/main.js` is the main player script — the audio graph, the library, every route and overlay, all ~536 top-level functions, importing `S` and the small shared helpers below rather than defining them inline (step 2b onward). A module now, not a classic script: nothing it declares at the top level is a property of `window` (confirmed nothing relies on that — see the step 2a PR). `src/miziki-social.js` stays a classic script loaded just before it, so `MizikiSocial` is already a real global by the time this runs.
- `src/state.js` exports `S` (the one app-state object — audio context, tracks, queue, mode, character settings, sessions, etc.; `S.scrubbing` was a top-level `let` in `main.js` until step 3c, see rule 7), `current()` (`S.tracks[S.index] || null` — moved here in step 3b since nearly every part of the app calls it), plus `SOCIAL_SUPABASE_URL` and `SOCIAL_SUPABASE_ANON_KEY`. The foundation every later extraction imports from.
- `src/storage/idb.js` exports `DB` (step 4a) — the raw IndexedDB wrapper: `open`, `put`, `get`, `all`, `clear`, `del`, moved out of `main.js`'s "persistence" section unchanged. Database name `miziki`, version 4, the eight stores and their key paths, the non-destructive `onupgradeneeded`, the 4-second open timeout and the `onblocked` handling are all exactly as they were. `main.js` still calls `DB.put`/`DB.get`/etc. directly about 100 times, and `MizikiSocial.mizikiAdapter({S, DB, …})` still receives it directly too — both unchanged for now; replacing the ~100 direct calls with a named interface (and commenting the one adapter call site that's allowed to keep using `DB` directly) is step 4c. No `onversionchange` handler yet — a known gap, see "Persistence rules" below.
- `src/storage/prefs.js` exports two pure functions (step 4b): `serializePrefs(S)`, the exact object `saveMeta()` has always written under `meta`/`prefs`, and `parsePrefs(raw)`, which returns a clean object containing only the fields that pass the same checks `applyPrefs()` has always made inline (same type checks, same allowed values — see "Persistence rules" below) — anything that fails a check, or is simply missing, is left out. `applyPrefs()` itself stays in `main.js`, unchanged, and now takes `parsePrefs(raw)`'s output instead of the raw saved object; `saveMeta()` now writes `serializePrefs(S)`. Splitting it this way makes the one part that matters for data safety — does an old or malformed saved object still load correctly — testable without a DOM.
- `src/storage/repo.js` (step 4c) — the named storage interface that replaced main.js's ~100 direct `DB.*` calls: one small object per store (`tracks`, `meta`, `sessions`, `achievements`, `collection`, `overlays`, `artwork`, `profile`), each with only the methods something in `main.js` actually calls, plus `storage.available()`/`storage.open()` replacing direct reads of `DB.ok` and the one `DB.open()` call. `meta.get(key)` returns the bare stored value instead of the `{k, v}` row every call site used to unwrap by hand; `meta.thumbs()` is the one place `main.js` scans all of `meta` rather than reading by key (artwork thumbnails), so it gets its own named method instead of a generic `all()`. `grep -n "DB\." src/main.js` finds only the two `MizikiSocial.mizikiAdapter({S, DB, …})` call sites (commented, since the adapter's own signature expects `DB`, not this interface) — no other direct `DB.*` call remains in `main.js`. A note at the bottom of the file (not built) records the App Store plan: blobs (`tracks.blob`, artwork blobs, `meta`'s `thumb:` blobs) would move to files on the device behind this same module, with callers unchanged.
- `src/util/dom.js` exports `$()` (a `document.querySelector` shorthand) and `el()`, the tiny `createElement` helper used ~450 times across the app.
- `src/util/async.js` exports `sleep()`.
- `src/util/text.js` exports `normKey()`, the normalization helper (lowercase, NFKD, strip diacritics/punctuation) used ~40 times app-wide for matching artist/album/title.
- `src/util/math.js` exports `clamp()`.
- `src/record-art/tiers.js` — quality tiers (`trackTier`) and variant selection (`albumKey`, `trackIdentityKey`, `VARIANT_DEFS`, `selectVariant`, `variantBackground`) for record-art rendering.
- `src/sundown/solar.js` — sun position math (`computeSun`, `solarEvent`, `nowClock`, `sunProgress`, `easedProgress`, `computeRate`) behind Sundown's auto playback rate.
- `src/sundown/location.js` — geolocation and Car Mode motion handling (`askLocation`, `fallbackSun`, `toggleSleevePull`, `toggleMotion`, `applyVolume`). Imports `drawSun` from `clock.js` and `queueSave` back from `main.js` (a deliberate circular import — see "Refactor rules" below).
- `src/crate/constants.js` — the small block of crate-view layout constants (`CRATE_ORIGIN_Y`, `CRATE_PALETTE`, `CRATE_VISIBLE_A`, `CRATE_DPR`, `CRATE_ALPHABET`).
- `src/player/sleep-timer.js` — the sleep timer (SLEEP spec §5): `updateSleepUI`, `stopSleepState`, `sleepStopPlayback`, `sleepCheckDeadline`, `openSleepSheet`, `closeSleepSheet`. Imports `pause` from `transport.js` and `drawTime` from `clock.js`. No longer imports anything from `main.js` (step 3c).
- `src/audio/engine.js` — the audio graph (`makeContext`, `buildGraph`, `satCurve`, `applyCharacter`, `routeSource`) and `ensureContext()` (from the "file loading" section — rebuilds the context when a file's sample rate differs). Imports `drawTime`/`settleTrackEnd` from `clock.js`, `setPathNote` from `ui/path-note.js`, `advance`/`preloadNextTrack` from `player/queue.js`, `ensureBuffer` from `player/buffers.js`, `sessionOnLoad`/`touchActiveSession` from `history/sessions.js`, and `updateCreditsButtonForCurrent`/`updateFavoriteButtons` from `library/credits.js`/`library/favorites.js` (all real imports as of step 5a/5c/5e, previously circular through `main.js`), and ~11 more functions back from `main.js` (circular, same reason as above) — screen updates and background-playback helpers it calls directly, in the same order as before. - `src/player/scrub.js` — spin-to-scrub (step 3c): `wireSpinToScrub`, `angleDelta` (exported for its unit test, same as `solarEvent` in step 2c), and their constants. Imports `drawTime` from `clock.js` and `pause`/`play`/`seek` from `transport.js` — no `main.js` import. Since F2, this is also where true scratching lives: when a gesture is claimed in Vinyl with `S.char.scratch` on, it lazily loads `src/audio/scratch-processor.js` into an `AudioWorkletNode`, copies a ±10s window of the current track's decoded channel data to it, and streams `target`/`window` messages to it on every `pointermove` (see `SCRATCH_SEC_PER_ROTATION`, `SCRATCH_WINDOW_SEC`). Scratch off, or Pure mode, falls back to the original silent fast-scrub unchanged.
- `src/audio/scratch-processor.js` — the F2 `AudioWorkletProcessor` scrub.js loads to produce real scratch audio. A plain classic script — no `import`, no `export` — both because Vite copies it verbatim via `new URL(..., import.meta.url)` in `scrub.js` rather than bundling it, and because Safari's AudioWorklet module loader has not reliably supported ES module syntax in the processor file itself (an early version that used `export` worked on desktop but silently produced no scratch audio on an iPhone). `tests/unit/scratch-processor.test.js` loads its source with Node's `vm` module to reach its pure math (`clampIndex`, `sampleAt`, `onePole`, `velocityEnvelopeTarget`) instead of importing it.
- `src/ui/path-note.js` — `setPathNote()` (step 3c), the general on-screen note helper. It happened to live in the spin-to-scrub section but isn't about scrubbing, so it got its own module rather than moving into `scrub.js`. No `main.js` import.

## How the app is put together

- **Global state** lives in one object, `S` (audio context, tracks, queue, mode, character settings, sessions, etc.), plus ~89 other top-level variables and ~536 top-level functions that share scope. Expect hidden coupling through `S` and these globals.
- **Audio:** Web Audio graph (`AudioContext`, `decodeAudioData`). There are two paths: **Pure** (reference — the character chain fully disconnected, not just turned down, **and** the playback rate always exactly 1.0; "Pure means untouched") and **Vinyl** (wow & flutter → saturation → top-end softening → bus compression, in that order, **and** Sundown's rate change). Sundown (auto and manual) only ever reaches the recording in Vinyl — `computeRate()` in `src/sundown/solar.js` returns `1` outright when `S.mode === 'pure'`, the one place that rule lives (see F1). Car Mode volume, the sleep-timer fade and the user's own volume still apply in Pure: those are level changes downstream of the recording, not changes to it, so "untouched" doesn't cover them.
- **Scratch (F2):** in Vinyl, with the Character menu's Scratch toggle on (default), spinning the disc by hand plays the real track forward/backward at the hand's speed via an `AudioWorkletNode` (`src/audio/scratch-processor.js`), joining the Vinyl chain at the same point the normal source does. Scratch off, or Pure mode, keeps spin-to-scrub as an invented, silent fast-navigation gesture (as it always was). Scratch is saved in `S.char.scratch` alongside the sliders; a saved-prefs object from before F2 has no such field, and a missing value means On.
- **Car Mode** raises volume with GPS speed. Speed always comes from GPS and never from the accelerometer.
- **Background playback** is optional and routes through a media element plus `navigator.mediaSession` for lock-screen controls. It works on iPhone today, so don't regress it.
- **Persistence:** IndexedDB database `miziki`, **version 4**, with stores `tracks`, `meta`, `sessions`, `overlays`, `artwork`, `profile`, `achievements` and `collection`. It holds the original files plus tags, so the library survives restarts. If storage is unavailable, every call no-ops and the app runs session-only.
  - **Never rename the database or drop or rename a store.** Users' libraries live there. Schema changes go through a version bump with a non-destructive `onupgradeneeded`.
  - **Any future version bump must come with a new upgrade test in `tests/unit/idb.test.js`** that starts from the previous version's real store layout, with data in it, and confirms every old record survives the upgrade and only the new stores/fields are added. This is the test in the "upgrade keeps data" case that would fail if anyone ever wrote a destructive upgrade — see step 4a.
  - **Known gap (not yet fixed): no `onversionchange` handler.** When a future version ships, an old copy of the app still open in another tab or window would block the upgrade rather than closing out of the way. Fix this when version 5 actually ships, not preemptively.
  - **Every new saved setting goes into both `serializePrefs` and `parsePrefs`** (`src/storage/prefs.js`, step 4b), **gets a default in `S`** (`src/state.js`), **and gets a test in `tests/unit/prefs.test.js`** that an old saved object without it still loads, with that default in place.
  - **`src/history/` is the only place that writes listening counters** (play counts, session counts, the metal-eligible shadow counters, rare unlocks, last-played timestamps — step 5c). Anything elsewhere that needs to touch one of these should go through `played.js`/`sessions.js`/`clear.js`'s exported functions rather than writing `S.trackPlayCounts`/`S.sessionCounts`/etc. directly.
  - IndexedDB is tied to the origin. Moving the app to a new domain (or a native shell) starts users with an empty library unless there is a migration or export path. The same goes for saved prefs in the `meta` store, including toggles like **Background playback** — a fresh origin starts with `S.bgAudio = false` (the default in `state.js`), even if it's on at the usual URL. This is why background/lock-screen playback can look broken on a Netlify preview the first time: the fix is to flip the toggle on there too, not a code change.
- **Social config:** `SOCIAL_SUPABASE_URL` and `SOCIAL_SUPABASE_ANON_KEY` are empty, which means the social layer is inert. supabase-js loads from the jsDelivr CDN only when social is enabled. The anon key is safe in client code because RLS is the real protection.
- `?social=demo` turns on a dev-only demo mode for the social screens. It must not run in production.
- Fonts come from Google Fonts (Antonio, Archivo, IBM Plex Mono).

## Refactor rules (modularization in progress)

1. **No behavior changes in refactor PRs.** A move is a move. Fixes and features go in separate PRs.
2. **One extraction per branch and PR**, small enough to review as a diff.
3. **Deployed URL must not change:** it stays `https://esang-mao.github.io/Miziki/miziki.html`, because the home-screen app is saved to that URL. The build must keep base path `/Miziki/` and output a file named `miziki.html`.
4. Prefer ES modules with explicit imports and exports over new globals. When a module needs `S`, import a shared `state` module rather than reaching for `window`.
5. Keep the section comments and spec references (e.g. "CREDITS spec §2") when moving code. They are the project's design history.
6. After every extraction, run the build, then the device checklist below.
7. **An importing module cannot reassign an exported `let`.** Live bindings are read-only on the import side — only the module that declared the `let` can assign to it. `const` exports are fine to mutate *properties* of (e.g. `S.tracks = …` on the exported `S` object), since that isn't reassigning the binding itself; the rule only bites for a top-level `let` whose value gets replaced wholesale. If code in one module needs to reassign a top-level `let` defined in another, either fold that value into `S` (so it's a property write, not a rebinding) or export a small setter function from the module that owns it. Never work around this with `window`. There are roughly two dozen such top-level `let`s still in `main.js` (`socialAuth`, `GF`, `SEALSHEET`, `saveTimer`, and others) — deal with one only once an extraction actually moves code across the boundary it crosses, not preemptively.
8. **An extracted module may import from `main.js` only as a temporary step**, and only use those imports inside functions, never at module top level — the same shape as the circular imports from step 2c. Each later extraction should move those targets out of `main.js` too, so the number of imports from `main.js` keeps shrinking rather than growing. Modules currently importing from `main.js`:

### F2: true scratching in spin-to-scrub (feature, not a refactor)

Spinning the disc by hand in Vinyl, with the Character menu's new **Scratch** toggle on (default On), now plays the real track forward or backward at the hand's speed, instead of just moving the position silently. Scratch off, or Pure mode, is exactly today's silent fast-scrub, unchanged.

- Safari can't reliably play an `AudioBufferSourceNode` backward (negative `playbackRate`), so this is an `AudioWorkletNode`: `src/audio/scratch-processor.js`, loaded lazily the first time a scratch gesture happens via `ctx.audioWorklet.addModule(new URL('../audio/scratch-processor.js', import.meta.url))` in `src/player/scrub.js`. The `new URL(..., import.meta.url)` form is what makes Vite copy the file as a plain, unbundled asset (confirmed in the built output: `dist/assets/scratch-processor-*.js`, not inlined, not run through the JS bundler) so it resolves correctly and loads under both `/Miziki/` and `/` bases. It is reloaded into a fresh `AudioContext` if `ensureContext()` ever rebuilds one for a different sample rate (tracked by `moduleLoadedCtx` in `scrub.js`).
- **The worklet file has no `import` or `export`, not just no imports.** It originally exported its pure helpers for the unit test, which worked in every desktop browser tested but silently produced no scratch audio on an iPhone: Safari's AudioWorklet module loader has not reliably supported ES module syntax in the processor file itself, so an `addModule()` that resolves fine in Chrome/Firefox can still fail to actually register the processor in Safari — and `scrub.js` already treats that failure as "no scratch audio this session," by design, so there was nothing to see without a device's remote inspector. Fixed by making the file a plain classic script (no `export` at all); `tests/unit/scratch-processor.test.js` now loads its source with Node's `vm` module instead of `import`, since there's nothing left to import — a classic script's top-level `function` declarations become properties of the sandbox object it runs against, which is how the test reaches the pure helpers, and `registerProcessor()`'s own call is still how it reaches the processor class (same as the real worklet; `class` declarations never become global properties, imported or not).
- **The playhead follows position, not velocity.** `scrub.js` sends the worklet a `target` (absolute track seconds) on every `pointermove`; the worklet moves its own `playhead` toward that target with a one-pole follower (`onePole()`, time constant `FOLLOW_TIME_CONSTANT`) and reads the loaded window at the resulting (possibly fractional, possibly decreasing) sample index with linear interpolation (`sampleAt()`). Reading a decreasing index plays the track backward — there's no separate "reverse" code path. **This is also where the pitch comes from**: advancing two samples of source per output sample plays an octave high, half a sample an octave low, exactly like vari-speed playback on a real turntable — no separate pitch-shifting step was needed or added. `FOLLOW_TIME_CONSTANT` was retuned from an initial `0.012s` up to `0.035s` because the tighter value let the playhead snap to each new touch sample almost instantly, which made real motion too brief to read as a held pitch — more a click per touch event than a scratch. `VELOCITY_FLOOR` (`0.05` → `0.03`) and `ENVELOPE_TIME_CONSTANT` (`0.01` → `0.02`) were loosened to match, so slow deliberate scratches stay audible instead of gating to silence between touch events.
- **Holding the disc still is genuine silence, not a frozen sample.** A fixed `target` would otherwise mean reading the same sample forever — a non-zero constant level, not silence. Loudness is tied to how fast the simulated platter is actually turning (`velocityEnvelopeTarget()`, floor `VELOCITY_FLOOR`, smoothed by its own one-pole so it doesn't buzz) the same way a real record is silent with the motor off and the needle resting on one groove point. This is deliberate, not just click-avoidance — see the comment at the top of `scratch-processor.js`.
- **Only a window of audio is ever copied to the worklet**, not the whole decoded track (tens of MB, and GitHub Pages can't send the `SharedArrayBuffer` headers): `loadScratchWindow()` in `scrub.js` copies ±10s (`SCRATCH_WINDOW_SEC`) of channel data around the current position via `Float32Array.slice()` (a real copy, so transferring its buffer to the worklet never detaches the track's own decoded `AudioBuffer`) and re-sends a new window once the position gets within `SCRATCH_REFETCH_MARGIN_SEC` of either edge.
- **Ratio:** `SCRATCH_SEC_PER_ROTATION = 1.8` (the real 33⅓ rpm speed) replaces `SCRUB_SEC_PER_ROTATION = 30` only when claimed as a scratch (Vinyl + Scratch on); otherwise the existing fast 30s/rotation navigation ratio is unchanged. Both constants are exported for their unit test.
- **Gain ramps (5–10ms)** at gesture start/end run on a plain `GainNode` between the worklet and `S.nodes.wobble` (not inside the worklet), scheduled with `linearRampToValueAtTime`. The node and gain are freed (`disconnect()`) once the end-of-gesture ramp finishes, so an idle worklet is never left running between gestures.
- **iOS:** `S.ctx.resume()` is called synchronously at the very top of the `pointerdown` handler, before anything else and before any `await` — the same rule `play()`'s `bgPrime()` follows, since iOS only allows resuming audio from inside the real user gesture. No `await` in the existing `play()`/`seek()` path was touched; release still goes through the unchanged `seek(S.pos)` then `play()` (only if it was already playing).
- **The toggle:** `S.char.scratch` (default `true` in `state.js`), alongside the other Character sliders in the saved prefs' `char` object. `applyPrefs()` special-cases it (the existing `char` merge loop only accepts numbers, since the sliders are percentages) and a saved value's absence leaves the default (On) in place — no IndexedDB version bump, since it's just a new field inside the existing `prefs.char` object. New row in the Character panel (`#scratchBtn`, styled like `#sleevePullBtn`).
- **Falls back safely:** if `addModule()` or the `AudioWorkletNode` constructor ever throws (unsupported browser, bad build), `scrub.js` logs a warning, sets a module-level `scratchSupported = false`, and every future gesture behaves exactly like Scratch-off — scratching is never allowed to break ordinary spin-to-scrub.
- `tests/unit/scratch-processor.test.js`: reads the worklet file's source and runs it with Node's `vm` module in a sandbox stubbing the AudioWorkletGlobalScope globals (`AudioWorkletProcessor`, `registerProcessor`, `sampleRate`), then exercises both the pure math (`clampIndex`, `sampleAt`, `onePole`, `velocityEnvelopeTarget`, reached as properties the sandbox's global object gained from the script's top-level `function` declarations) and the full `process()` loop on fake buffers: a continuously-advancing target produces forward motion, a continuously-retreating one produces reverse, a target held still after one small move settles to near-silence, and the playhead/reads never leave the loaded window or the track. `tests/unit/clock.test.js` gained one more test confirming the 1.8s/30s rotation ratio constants.
- Verified: both builds (`npm run build`, `MIZIKI_BASE=/ npm run build`) emit the worklet as its own asset, confirmed free of `export`/`import` in the built output; `npm run test:unit` passes (34/34); a Playwright script dragged the disc in a real Chromium past the 8° claim threshold against both built targets with `AudioWorklet.prototype.addModule`/`AudioParam.prototype.linearRampToValueAtTime` spied from outside the module (nothing is exposed on `window`) — Vinyl + Scratch on produced a matched ramp-up/ramp-down pair per gesture (while paused and while playing), Scratch off and Pure mode produced none, and `?social=demo` stayed clean. No console or page errors beyond the known baseline 404. The ESM-syntax fix and the retuned constants are desktop-Chromium-verified only — Playwright can't stand in for Safari here, so the actual sound and whether scratching now works at all on an iPhone still needs Ken's device.
